D1 experiment notes
===================

Planned runs:

1. run_1: MLP-F15 on the frozen D1 dataset.
2. run_2: causal GRU-F15 on the identical D1 split.
3. Compare K in {1,2,3,5} on validation data only.

Each run writes its own notes.txt and final_info.json. Results from pilot or smoke

  then sample one continuous strength uniformly inside the matching attack-specific
  interval; reuse that value for the complete event.
- Regression suite: 21 tests passed in 5.26 seconds.
- Data-path audit: 12 S-curve episodes produced exactly 3 clean, 3 random, 3 replay,

  strength summaries for every attack type.
- The 12-episode severity counts were weak=5, medium=3, strong=1. This small random
  draw is an implementation audit, not evidence of expected finite-sample balance.

Early-detection objective ablation (2026-07-19)
------------------------------------------------

- Data: d1_5000_rcs12_seed20260717; GRU-F15; class weighting none; seed 20260718.
- Paired objectives: ordinary BCE versus normalized onset-weighted BCE.
- Onset settings: 20-step window, 3x raw onset multiplier, 10-step exponential
  decay; positive temporal weights preserve total positive mass per UAV sequence.
- Both objectives use ordinary validation BCE for checkpoint selection, threshold
  0.5, and fixed K=5. Test is opened only after all settings are frozen.
- On test, DR@1s changes from 0.4779 to 0.4994 and conditional mean delay from
  1.918s to 1.826s, but FAR changes from 1.122 to 2.489 false alarms/UAV-hour and
  event F1 from 0.9354 to 0.9150.
- Decision: retain the objective as an optional research switch; keep ordinary BCE
  as the current primary method. This test result must not be used to tune onset
  weight parameters on the same frozen test split.

Event-risk feature ablation implementation (2026-07-19)
-------------------------------------------------------

- The five-set F15 feature ablation runner now defaults to event_risk_bce and
  forwards one fixed K, time step, delay weight, false-alarm weight, and miss
  penalty to every feature-set run.
- Resume mode verifies the complete data/model/loss signature before reusing a
  result, preventing ordinary-BCE and event-risk runs from being mixed.
- Summaries now include DR@0.5/1/2/5s, clean-episode alarm probability, conditional
  mean/median delay, event metrics, step metrics, and false alarms/UAV-hour.
- No feature-ablation result is recorded here yet. Loss hyperparameters must be
  frozen on validation before opening the test split.

Historical state-machine event-likelihood replacement (superseded 2026-07-21)
-----------------------------------------------------------------------------

- Removed the two active event-loss objectives `event_risk_bce` and
  `event_risk_monotonic`; the only non-BCE objective is now `event_likelihood`.
- This superseded objective used an absorbing K-state first-alarm probability model,
  event detection negative log likelihood, detection-conditional normalized
  delay, and length-normalized normal-interval no-alarm likelihood.
- Events shorter than K remain in step BCE but are excluded from event-level
  detection and delay terms and are counted as unobservable.
- Event terms can be ramped in over `event_ramp_epochs`; a matching BCE checkpoint
  can be loaded for fine-tuning without changing the frozen 0.5 threshold or K.
- Focused objective/CLI tests pass (29 tests), and the end-to-end simulated-data
  smoke test completes for both BCE and event_likelihood.

Complete-event data generation (2026-07-21)
-------------------------------------------

- Formal attack generation now samples the duration first and samples the onset
  uniformly only from the range in which the complete event fits in the episode.
- New datasets therefore satisfy `actual_duration_steps == nominal_duration_steps`,
  `end_step <= num_steps`, and `attack_was_truncated == False` for every attack.
- Legacy duration/truncation arrays are retained for storage compatibility. The
  manifest and the D1 wrapper audit the complete-event boundary policy explicitly.
- Existing datasets are not modified; a new output directory is required to use
  the revised sampling policy. Tests were updated but left for user execution.

Batched event-likelihood acceleration (2026-07-21)
--------------------------------------------------

- Replaced per-interval scalar state-machine calls with padded batched attack and
  normal-interval evaluation while preserving the same first-alarm probabilities.
- The state machine now accepts `(B,T)` logits plus a validity mask, so one time
  loop updates all intervals in a minibatch on the GPU.
- A representative CPU benchmark with 32 variable-length 600-step intervals took
  0.0590 s batched versus 1.9953 s scalar (33.79x for the state-machine forward).
- Added batch progress logging every 100 minibatches and at the end of each loader.
- Focused tests pass (27), including scalar/batch equivalence and finite-gradient
  checks; the end-to-end BCE/event-likelihood smoke training also passes.
- A second optimization merges attack and normal intervals into one padded state
  batch, vectorizes label-run extraction with NumPy, and executes the remaining
  time recurrence in a cached TorchScript graph. On a representative CPU forward,
  the merged full objective took 0.0452 s versus 0.0566 s for two state passes.

Soft-Min K-step hazard replacement (2026-07-21)
------------------------------------------------

- Removed the recurrent differentiable K-state training layer after a formal BCE
  checkpoint produced non-finite first-alarm values and delay gradients on long,
  high-confidence attack intervals.
- The active `event_likelihood` objective now maps every complete K-logit window
  through a normalized Soft-Min and a conditional alarm hazard. Exclusive
  cumulative log survival yields the first-alarm likelihood without state
  normalization or probability-space products.
- Detection and conditional-delay terms are computed in log space; the hard
  `p >= 0.5` plus K-consecutive-positive state machine remains unchanged for
  deployment and reported event metrics.
- Training now rejects non-finite objectives before an optimizer step and rejects
  non-finite gradient norms, preventing invalid checkpoints from being selected.

Unified validation-loss checkpoint selection (2026-07-21)
----------------------------------------------------------

- BCE and `event_likelihood` now both update `best_model.pt` only when validation
  total loss strictly decreases; hard event F1 and its tie-break metrics are no
  longer used for checkpoint ranking.
- Event terms may still ramp into the training loss, but validation always uses
  the full event objective (`event_loss_scale=1`) so validation losses remain
  comparable across epochs.
- Hard event precision, recall, F1, false alarms, and delay remain validation
  diagnostics and are not checkpoint-selection inputs.

3GPP UMi-AV Deep Ensemble channel update (2026-09-01)
------------------------------------------------------

- Replaced the fixed 4 dB path-loss deviation, the additional 0.5 dB
  measurement error, and the assumed 0.5 actual/theoretical correlation with
  the height- and LoS/NLoS-dependent UMi-AV shadow-fading deviations from
  3GPP TR 36.777.
- Actual path-loss observations now sample the physical link state from the
  standard LoS probability and apply the corresponding shadow fading. The
  GPS-implied set is the theoretical expected path loss computed from the
  reported position and contains no independently invented noise term.
- Six focused tests passed by direct invocation. A one-episode feature-generation
  smoke test completed for each train, validation, and test split under the full
  E = 150 setting. The generated feature tensor has shape (1, 600, 8, 4, 10) and
  contains only finite values.
- Existing Deep Ensemble feature caches are invalidated automatically because
  the sidecar completion marker records the full path-loss configuration.

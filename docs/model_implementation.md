# 新建模方案的代码实现

本文对应 [完整建模方案](isac_model_improvement/complete_model.md)，说明模型如何进入仿真、定位、特征、导航和评价。配置入口为 `configs/default.json`，多轨迹入口为 `configs/multitrajectory_crb.json`。

当前暂时关闭报警后的导航缓解。默认 `navigation.enabled=true`、`navigation.mitigation_enabled=false`，保留 GPS 反馈运动、ISAC 观测、定位、检测和告警记录。下文的 ISAC 导航切换仅在显式开启缓解后生效。

## 1. 本次改动

| 模块 | 当前实现 | 主要文件 |
|---|---|---|
| 运动 | 参考轨迹加位置反馈，合速度饱和，理想速度跟踪 | `environment.py`、`navigation.py` |
| GPS | 正常高斯误差与攻击注入，重放默认使用独立正常飞行记录，控制和检测共用同一次报告 | `gps_attacks.py`、`normal_recording.py` |
| 基站感知 | 分目标功率与带宽、单基地接收功率、空间频率与时延/Doppler CRB | `isac.py`、`config.py` |
| 机间感知 | 同一测距原理，替换功率、带宽、增益、观测时长及相对几何 | `isac.py` |
| 定位 | 带噪距离和角度的固定协方差加权最小二乘 | `localization.py` |
| 特征 | 保持 10 维，尺度计入正常 GPS 误差，方向项用二阶误差尺度 | `features.py` |
| 导航切换 | 当前默认关闭，显式开启后确认报警才在下一片锁定 ISAC 导航 | `environment.py`、`evaluation.py` |
| 数据与时间 | schema 3.0，单独记录观测时刻和片末可用时刻 | `types.py`、`data.py`、`metrics.py` |

上述 Python 文件均位于 `src/isac_spoofing/`。

## 2. 一个时间片如何运行

对默认的重放 episode，环境先完成一段独立正常飞行录制。录制源与本次受害飞行共享外生参考轨迹、初始队形和 UAV 索引，使用独立的正常 GPS 噪声驱动自己的位置反馈运动，不生成源 ISAC 观测或告警缓解。录制完成后才递推受害飞行，因此录制源不受受害飞行中的攻击和轨迹偏移影响。

1. 环境持有受害 UAV 的片初真实位置，生成一次正常 GPS 报告，再施加本片攻击。默认重放从已完成的正常记录中复制对应 UAV 的样本，不再叠加正常 GPS 噪声。
2. 初始导航使用本片 GPS。已锁定 ISAC 的 UAV 使用上一片定位加上一片已知指令位移。
3. 控制器由参考位置、参考速度和导航输入计算本片速度指令，再限制合速度。理想执行速度等于该指令。
4. 本片几何近似不变。前半片机间轮流发射，后半片各基站在各自频段并行感知。保留速度及 Doppler 效应。
5. 环境根据真实几何、物理接收功率和 CRB 生成带噪观测。处理端根据功率报告和带噪角度计算报告协方差，完成定位及特征构造。
6. 片末检测器输出每机攻击概率并记录确认告警。当前默认不改变导航模式；显式开启缓解后，连续确认才触发下一片的导航模式锁定。误报同样触发，不读取攻击标签决定切换。
7. 位置按本片执行速度递推，进入下一片。

仿真中的运动递推和测量生成在代码内顺序执行，表达的是同一离散时间模型，不代表在测量完成前获得本片检测结果。

## 3. 真值、观测与质量报告

生成端使用真实位置、速度、接收功率及生成协方差。这些数组用于环境生成和离线审计。检测网络的输入只有特征。

处理端使用带噪距离、角度、径向速度、机间距离、已知指令，以及报告协方差。当前准确质量报告假设为 $\hat P_r=P_r$，属于显式仿真参考条件，并未实现实际接收功率估计器。处理端不会用 GPS 距离反推功率，也不读取真实位置生成定位结果。

基站观测在 $[d,\theta,\phi,v_r]$ 上抽样一次，方向由带噪角度计算，不再次叠加方向噪声。报告协方差使用带噪角度，因此通常与生成协方差不同。位置不另抽一次噪声，而由这些观测做加权定位。

采用 CRB 为协方差仍是理想估计参考。当前不模拟具体波形估计器、多径、错关联、漏检或硬件校准，代码实现不能证明实际设备达到该精度。

默认 `attack.replay_source=recorded_normal_episode`。重放在第 $t$ 片读取正常记录的第 $t-d$ 个样本，$d$ 表示源轨迹相位偏移，不表示实时链路延迟。受害飞行的真实位置、未受攻击 GPS 和 ISAC 观测仍来自受害飞行自身状态，不被源记录替换。可选的 `delayed_clean_stream` 保留原来的受害飞行历史正常 GPS 重放。

每个重放 episode 使用自己的完整正常记录。源 GPS 数组保存在仅供审计的 `replay_source_gps_m` 中，非录制源 episode 在同形数组中填零，通过 `metadata.replay_recording.present` 区分，不将零值解释为有效记录。元数据记录源 ID、受害 seed、录制 seed、UAV 索引映射和实际使用的源索引范围。录制 seed 只确定源 GPS 噪声，复现还需对应的参考轨迹、初始状态和受害 seed。源数组不进入检测器，特征维度仍为 10。

## 4. 资源与配置

| 配置量 | 默认值与含义 |
|---|---|
| 时间片 | 20 ms，GPS、控制和检测每片更新 |
| BS 观测时长 | 后半片 10 ms，每目标并行观测 |
| 机间观测 | 前半片轮发，每机 1 ms，不单列保护时间 |
| BS 带宽 | 全网 160 MHz，每站 40 MHz，8 机时每目标 5 MHz |
| BS 功率 | 每站总计 27 dBm，按目标均分 |
| BS 阵列 | 收发均为 8×8，半波长间距 |
| 机间配置 | 3 GHz、30 MHz、0 dBm、有效发射增益 1、有效接收增益 16 |
| GPS 标准差 | 水平每轴 1.5 m，垂直 3.0 m，用户选定的主实验参考 |
| 控制 | 水平/垂直增益 0.95/1.0 s⁻¹，合速度上限 8 m/s |
| 确认窗口 | 固定连续 5 片，当前 20 ms 下对应 100 ms，调整时间片长度不改变确认片数 |
| 场景 | 60 s、8 机、立方编队，具体攻击分档和站位见配置 |

机间一次发送服务多个充分分离的邻机，不重复分摊或计入发射功率和带宽。有效接收增益 16 已包含机载阵列增益，后续不再乘 16。基站则向不同 UAV 分配独立通信感知资源，必须使用每目标资源。

默认四站保持原水平坐标，高度统一为 0 m，固定采用上半空间。代码对奇异角域或覆盖半空间违反显式报错，不读取真值动态选择角度分支。改变部署或增加机群规模时，需要同时检查覆盖和轮发时长。

## 5. 采集、训练与在线缓解

`generate_dataset` 采集共同 GPS 反馈闭环数据。此时没有训练好的检测器，报警不会回灌导航。这一模式仍会产生攻击导致的实际运动偏移。

在线使用 `ISACSpoofingEnvironment.run_episode(detector=...)`。回调仅接收形状为 `(N,10)` 的特征，返回 `(N,)` 攻击概率。冻结 GRU 的隐藏状态在 episode 内延续，每个 episode 重置。默认只检测和记录告警，导航继续使用 GPS。显式开启缓解后，确认后的 ISAC 导航模式保持到 episode 结束。

`scripts/evaluate_navigation_mitigation.py` 要求配置显式开启缓解，对同一外部随机种子运行共同 GPS 反馈和在线缓解，分别报告事件指标、轨迹误差与编队距离误差。攻击标签及真实位置只用于运行结束后的评价。在线轨迹会在报警后变化，因此需要单独评价，不能把离线共同轨迹检测结果当作闭环安全结论。

## 6. 兼容与迁移

- 旧经验误差配置保留为历史文件，并标记 `legacy_effective_echo`。新加载入口明确拒绝把这些文件当作当前 CRB 配置。
- 旧 RCS 等效系数不自动转换成物理 RCS，旧孔径参数不参与当前 CRB。
- 当前默认配置明确选择 `recorded_normal_episode`。旧保存配置若缺少 `attack.replay_source`，加载时保持 `delayed_clean_stream` 语义，避免将历史实验静默改成独立正常记录重放。
- 新数据保存片初 `time_s` 与片末 `available_time_s`。确认于片索引 $t$ 触发时，延迟为 $(t-t_0+1)\Delta t$。
- 旧数据缺少新时间标记时沿用原索引计时。数据不会被静默重标为 schema 3.0。
- 新检查点记录源模型配置和时序。在线入口拒绝无来源或不匹配的检查点，显式允许域变化时标记为未验证。
- 新模型需要重新生成数据并重训。单轮功能检查的权重不代表论文结果。

## 7. 验证记录

以下上一轮验证记录采用 GPS 标准差 (0.5,0.5,1.0) m。2026 年 10 月 30 日主配置更新为 (1.5,1.5,3.0) m，后续数据必须按新配置生成。

已完成 CRB 的带宽、时长和距离尺度检查，经验噪声方差检查，真值审计字段不参与特征的检查，以及加权定位、角度跨界、正常 GPS、历史重放、下一片切换、数据读写和事件时序检查。

已运行 71 项核心与相关回归测试。另完成 10 个短 episode 的分片数据生成、单轮 GRU 训练和冻结检查点在线评估入口检查。这些验证确认代码链路可运行，不用于评估检测准确率。

随后新增的流式推理与机间辅助入口检查，连同新模型专项回归共 18 项通过。四种参考轨迹与四种场景的 16 组短期动力学核查通过，可控误报在默认第 24 片确认、第 25 片开始 ISAC 导航。默认 60 s 的 clean、random、replay、stealth 四类场景在种子 21 下均完成 3000 片，无非有限值或角域异常。

时序与基线分组回归另记录 53 项通过、13 项失败、2 项未完成后排除。13 项失败经对照迁移前目标原件，属于已有训练代码与测试的不一致，其中 1 项期待计入原已注释的 detection loss，12 项期待原件没有实现的采样策略或验证间隔接口。本次保留这些训练算法现状。两项 Deep Ensemble 测试在 sklearn 模型构造时长时间未完成，未报告为通过。各组测试存在交集，不能直接相加。

目标副本原有完整测试集包含五个缺失脚本的导入，导致全量收集失败，分别为 `analyze_ablation_by_attack_count.py`、`baseline_xgboost.py`、`run_early_detection_objective_ablation.py`、`run_feature_ablation.py`、`rebuild_inter_uav_neighbor_views.py`。本次没有把未运行的全量测试宣称为通过。
